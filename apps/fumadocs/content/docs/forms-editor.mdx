## Blocks

A block is anything you add to a form: a question (an **input** block) or something purely visual (a **layout** block). Click **Add block** to open the library and pick one.

**Input blocks** (collect an answer): Text, Rich text, Email, Phone, URL, Number, Date, Password, Dropdown, Single choice, Multiple choice, Checkbox, Toggle switch, Rating, Scale, Slider, Matrix, File upload, Signature, Barcode reader, QR code reader.

**Layout blocks** (no answer, just presentation): Text, Page break (classic style only), Divider (classic only), Image, Video, Audio, HTML code.

### Drag & drop, and widths

Drag the handle on the left edge of a block in the list to reorder it. On the canvas, a block can share a row with its neighbor: open its settings and set **Width** to Full, 3/4, 2/3, 1/2, 1/3, or 1/4 — fields are laid out on a 12-column grid, so two 1/2-width fields (or a 1/3 next to a 2/3) sit side by side automatically.

## Field settings

Click any field to open its settings panel on the right. Every field has:

- **Label** — the question text shown above the input.
- **Field ID** — the key this answer is stored under in submission data, URL pre-fill links, webhook payloads, @mentions, and logic conditions. It's auto-generated from the label for a brand-new field; once the field already has submissions, renaming it is still allowed (every reference inside the form updates automatically) but shown with a warning, because data already collected or an external integration that stored the old id won't follow along.
- **Hide label** — keeps the input but removes the visible label text above it.
- **Help text** — a short note shown next to the field, with basic rich formatting.
- **Width**, and for text blocks, text **alignment**.

Most input blocks group their settings into tabs:

- **General** — the common settings above, plus type-specific options (placeholder text, date format, rating scale, file size limits, and so on — see each block's own options when you select it).
- **Options** — for choice fields (Dropdown, Single choice, Multiple choice, Matrix): the list of options respondents can pick from. Drag to reorder, and for choice fields you can also attach an **image per option** — see [Classic vs. Focused style](/docs/form-styles#option-images).
- **Logic** — show, hide, require, disable, or re-enable this field automatically based on other answers.
- **Validation** — reject an answer unless it meets conditions you set, with a custom error message.

Layout blocks (Text, Image, Video, HTML code…) only show **Content** and **Logic**, since there's no answer to validate.

### Logic (conditions)

Open a field's **Logic** tab to build a condition — "if `<field>` `<is/contains/is greater than/…>` `<value>`" — combined with AND/OR into a tree. When the condition is met, StryveForms can:

| Action | Effect |
| --- | --- |
| Show field | Reveals a field that starts hidden |
| Hide field | Removes the field (and its answer) from the live form |
| Require answer | Respondents must answer before submitting |
| Make it optional | Respondents can submit without answering it |
| Disable field | Field stays visible but respondents can't edit it |
| Enable field | Re-enables a field that starts disabled |

### Pages

In **classic** style, add a **Page break** block anywhere to split the form into pages — respondents see a **Next**/**Previous** bar and a progress indicator. (Focused style already shows one question per "page" by design, so page breaks don't apply there — see [Classic vs. Focused style](/docs/form-styles).)

### Hidden fields & prefill

Any field can be marked **hidden** from its Logic tab (hidden by default, with logic to reveal it — or left permanently hidden with no logic at all). A permanently hidden field is useful for capturing a value you set yourself rather than ask the respondent for, most often combined with a **prefill** default or a [URL prefill link](/docs/sharing#prefilling-the-form-with-a-url):

```
https://yourdomain.com/forms/my-form?lead_source=newsletter
```

Since the query parameter's key is the field's id, a hidden `lead_source` field quietly records which link someone clicked, with no extra UI for them to see.

### Computed variables

Open the form's **Settings → Variables** tab to define a computed variable: a name plus a formula that references other fields by id, e.g. `nights * 120`. Computed variables:

- Recalculate live as the respondent fills the form.
- Can be inserted anywhere @mentions work — a Text block, a redirect URL, an email notification — so you can show a running total, a calculated date, or any other derived value without asking for it directly.
- Support 38 built-in functions (math, text, date, and logic functions) — the formula editor autocompletes field names and functions as you type.

## Field validation (built-in)

Beyond the custom **Validation** tab, every field type has sensible defaults: Email checks for a valid address, URL checks for a valid link, Number only accepts digits, a required field blocks submission until answered, and so on. Character limits, min/max values, and similar per-type limits live in that field's **General** tab.
