StryveForms exists so that solid, polished form-building software doesn't have to live behind a paywall — a free, open-source, white-label alternative to OpnForm, Typeform and the like, that anyone can self-host and make their own. If that sounds worth helping with, you're in the right place.

The full guide — setup, coding standards, commit conventions, the PR checklist, and where help is most wanted — lives in [`CONTRIBUTING.md`](https://github.com/flyingwebie/stryveforms/blob/main/CONTRIBUTING.md) at the repository root. This page is the short version.

## Quick start

```bash
git clone https://github.com/flyingwebie/stryveforms.git
cd stryveforms
bun install
cp apps/server/.env.example apps/server/.env   # set BETTER_AUTH_SECRET: openssl rand -base64 48
cp apps/web/.env.example apps/web/.env
bun run db:start
bun run db:push
bun run dev
```

Needs [Bun](https://bun.sh) 1.3+ and Docker (only for the local Postgres container). Open `http://localhost:3002` and run through onboarding.

## Before you open a PR

- `bunx ultracite fix` — auto-formats to this project's [Ultracite](https://ultracite.dev)/Biome standards
- `bun run check-types` — type-checks the workspace
- `bun test` inside any package you changed logic in
- Screenshots in **light and dark mode** for any visible UI change

## Where to help

- **Integrations** — new notification/automation destinations
- **Importers** — OpnForm and JotForm field/setting coverage
- **Translations** — the UI isn't internationalized yet
- **Documentation** — this site always has gaps, deployment guides for more platforms are especially welcome
- **Templates** — starter forms for common use cases

See [`CONTRIBUTING.md`](https://github.com/flyingwebie/stryveforms/blob/main/CONTRIBUTING.md) for the repo map, commit message convention (Gitmoji + Conventional Commits), and the full PR checklist.
